# Виджет банковских операций

Виджет для отображения последних успешных банковских операций клиента в личном кабинете банка.

## Цель проекта

Разработать виджет для IT-отдела крупного банка, который позволяет клиентам видеть свои последние банковские операции и их статус в личном кабинете.

## Основные функции

- **Отображение успешных банковских операций**
- **Маскировка номеров карт и счетов** для безопасности
- **Фильтрация операций** по статусу выполнения
- **Сортировка операций** по дате
- **Форматирование дат** в удобный для чтения формат

## Технологии

- Python 3.13+
- Библиотеки: `requests`, `datetime`, `python-dotenv`, `pandas`, `re`

### Рабочий процесс приложения

#### Этап 1: Выбор источника данных
Пользователь выбирает один из трех доступных форматов:
1. **JSON-файл** - через `unpacking_json_file("operations.json")`
2. **CSV-файл** - через `csv_reader()` с путем `data/transactions.csv`
3. **XLSX-файл** - через `xlsx_reader()` с путем `data/transactions_excel.xlsx`

#### Этап 2: Фильтрация по статусу
Пользователь выбирает статус транзакций:
- `EXECUTED` - выполненные операции
- `CANCELED` - отмененные операции  
- `PENDING` - ожидающие операции

Фильтрация выполняется функцией `filter_by_state()`

#### Этап 3: Настройка дополнительных параметров
Интерактивный диалог с пользователем:
1. **Сортировка по дате** - с выбором направления (возрастание/убывание)
2. **Фильтр по валюте** - возможность отображать только рублевые транзакции
3. **Поиск по описанию** - фильтрация по ключевому слову в описании

#### Этап 4: Обработка и вывод результатов
Применение выбранных фильтров и сортировок:
- Сортировка: `sort_by_date()`
- Валютный фильтр: `filter_by_currency()`
- Поиск по описанию: `process_bank_description()`

#### Этап 5: Отображение результатов
Форматированный вывод всех подходящих транзакций с помощью `filter_transaction()`

### Модуль `processing.py`

Модуль содержит функции для фильтрации и сортировки банковских операций.

Функция фильтрует список операций по статусу выполнения.

**Параметры:**
- `operation_list` - список словарей с операциями
- `state` - статус для фильтрации (по умолчанию "EXECUTED")

**Внимание! Фильтрация в данный момент осуществляется только по 2 аргументам EXECUTED и CANCELED**

**Возвращает:**
- Новый список словарей, в которых значение ключа 'state' равно аргументу

**Пример использования:**

```python
from src.processing import filter_by_state

# Пример данных операций
operations = [
    {
        "id": 1,
        "state": "EXECUTED",
        "date": "2024-01-15T14:30:00Z",
        "amount": "1000",
        "currency": "RUB",
        "description": "Перевод организации"
    },
    {
        "id": 2,
        "state": "CANCELED", 
        "date": "2024-01-14T10:15:00Z",
        "amount": "500",
        "currency": "USD",
        "description": "Перевод другу"
    }
]

# Фильтрация выполненных операций
executed_operations = filter_by_state(operations, "EXECUTED")
print(executed_operations)
# [{'id': 1, 'state': 'EXECUTED', 'date': '2024-01-15T14:30:00Z', ...}]
```

### Модуль `decorators.py`
Модуль содержит декоратор для логирования выполнения функций:

### log(filename=None)
**Назначение:** Декоратор для записи логов выполнения функций в файл или вывод в консоль

**Параметры:**

- `filename` - имя файла для записи логов (опционально). Если не указан, логи выводятся в консоль

- `Возвращает:` Декоратор функции

#### Особенности:

- Записывает время вызова, имя функции и статус выполнения

- Логирует как успешное выполнение, так и ошибки

- При ошибках записывает тип исключения, сообщение и входные параметры

- Сохраняет метаданны оригинальной функции (имя, документацию)

- Файлы сохраняются в папку data относительно базовой директории проекта

**Поведение:**

- При успешном выполнении: `{дата} - {имя_функции} - ok`

- При ошибке: `{дата} - {имя_функции} error: {тип_ошибки} - {сообщение}. Inputs: {args}, {kwargs}`

**Примеры использования:**

```bash
# Логирование в консоль
@log()
def add(a, b):
    return a + b

# Логирование в файл
@log("operations.log")
def multiply(x, y):
    return x * y

# Логирование функций с исключениями
@log("errors.log")
def risky_operation(data):
    if not data:
        raise ValueError("Empty data")
    return process(data)
```
**Исключения:**

- Обрабатывает все исключения, возникающие в декорируемой функции

- При ошибке возвращает `None` и записывает информацию об ошибке в лог

**Формат логов**
```
30.11.2025 10:30:45 - add - ok
30.11.2025 10:31:20 - add error: ValueError - Empty data. Inputs: ([],), {}
```

### Модуль `utils.py`

Модуль содержит утилиты для работы с файлами и обработки финансовых транзакций:

### Настройка логгера
- Настраивает логгер с именем "utils" и уровнем DEBUG
- Создает файловый обработчик для записи в `logs/utils.log`
- Использует формат: `%(asctime)s - %(name)s - %(levelname)s - %(message)s`

### unpacking_json_file(file_name: str)
**Назначение:** Десериализация JSON файла в Python объект

**Параметры:**
- `file_name` (str) - имя файла в формате .json

**Возвращает:**
- `Union[List[Dict[str, Any]], Dict[str, Any]]` - десериализованные данные или пустой список при ошибке

**Особенности:**
- Ищет файлы в папке `data` относительно базовой директории проекта
- Поддерживает как списки, так и словари в качестве корневого элемента JSON
- Логирует все этапы выполнения и ошибки

**Поведение:**
- Успешное выполнение: `Успешно десериализовали файл`
- Ошибки: логирует тип исключения и сообщение с уровнем CRITICAL
- При неверном формате данных возвращает пустой список


### extract_transaction_amount(unpacked_json_transactions)
**Назначение:** Извлечение суммы транзакции с конвертацией в рубли

**Параметры:**
- `unpacked_json_transactions` - десериализованные данные транзакции (список или словарь)

**Возвращает:**
- `float` - сумма транзакции в рублях или 0.0 при ошибке

**Особенности:**
- Обрабатывает как одиночные транзакции (словарь), так и списки транзакций
- Для валют EUR и USD выполняет конвертацию через внешний API
- Для RUB возвращает сумму без конвертации
- Логирует все этапы обработки и ошибки

**Поведение:**
- Успешное выполнение: `Валюта конвертировалась корректно` или `Код валюты - российский рубль. Возврат суммы`
- Ошибки: логирует тип исключения и сообщение с уровнем CRITICAL
- При пустом списке или некорректных данных возвращает 0.0

**Примеры использования:**
```python
# Обработка списка транзакций
transactions = unpacking_json_file("operations.json")
amount = extract_transaction_amount(transactions)

# Обработка одной транзакции
transaction = transactions[0]
amount = extract_transaction_amount(transaction)
```

### Модуль `external_api.py`

Модуль содержит функции для работы с внешними API:

### api_convert(currency_code: str, amount: str | float)
**Назначение:** Конвертация валюты в рубли через внешний API

**Параметры:**
- `currency_code` (str) - код валюты для конвертации (только "EUR" или "USD")
- `amount` (str | float) - сумма для конвертации

**Возвращает:**
- `float` - сконвертированная сумма в рублях или 0.0 при ошибке

**Особенности:**
- Использует API сервиса apilayer.com
- API ключ загружается из переменных окружения через .env файл
- Поддерживает только конвертацию EUR→RUB и USD→RUB
- При других валютах сразу возвращает 0.0

**Поведение:**
- Успешная конвертация: возвращает сумму в рублях
- Неподдерживаемая валюта: возвращает 0.0 без вызова API
- Ошибка API: выводит информацию об ошибке в консоль и возвращает 0.0

**Примеры использования:**
```python
# Конвертация евро
rub_amount = api_convert("EUR", 100)

# Конвертация долларов
rub_amount = api_convert("USD", "50.5")
```

**Зависимости:**
- Требует установленных пакетов: `requests`, `python-dotenv`
- Требует наличия переменной окружения `API_KEY` с ключом от apilayer.com
- Использует базовый URL: `https://api.apilayer.com/exchangerates_data/convert`

### Модуль `finance_parser.py`

Модуль `finance_parser.py` содержит функции для чтения и обработки финансовых данных из файлов CSV и Excel форматов. Модуль включает настройку логирования для отслеживания операций и обработки ошибок.

#### Структура модуля

### Логирование
Модуль настраивает логирование в файл `logs/finance_parser.log` с уровнем `DEBUG`. Логи содержат временные метки, имя модуля, уровень логирования и детали операций.

### Функции модуля

#### 1. `scv_reader(path_to_file)`
**Назначение:** Читает CSV файл и преобразует его данные в список словарей  
**Параметры:**
- `path_to_file` - путь к CSV файлу (строка или объект Path)
**Возвращает:**
- Список словарей с данными из CSV файла
- Пустой словарь `{}` в случае возникновения ошибки
**Логирование:**
- Информационные сообщения о получении пути, проверке существования файла и его размера
- Сообщение об успешной обработке файла
- Сообщение об ошибке с деталями исключения

#### 2. `xlsx_reader(path_to_file)`
**Назначение:** Читает Excel файл (формат XLSX) и преобразует его данные в список словарей  
**Параметры:**
- `path_to_file` - путь к Excel файлу (строка или объект Path)
**Возвращает:**
- Список словарей с данными из Excel файла
- Пустой список `[]` в случае возникновения ошибки
**Логирование:**
- Информационные сообщения о получении пути, проверке существования файла и его размера
- Сообщение об успешной обработке файла
- Сообщение об ошибке с деталями исключения

### Пример использования

```python
from src.finance_parser import csv_reader, xlsx_reader
from src.config import BASE_DIR

# Чтение CSV файла
csv_data = csv_reader(BASE_DIR.joinpath("data", "transactions.csv"))

# Чтение Excel файла
excel_data = xlsx_reader(BASE_DIR.joinpath("data", "transactions_excel.xlsx"))
```

### Особенности работы

1. **Проверка существования файла:** Обе функции проверяют, существует ли указанный файл
2. **Проверка размера файла:** Функции проверяют, что файл не пустой
3. **Обработка ошибок:** Все исключения перехватываются и логируются, функция возвращает пустую коллекцию в случае ошибки

### Модуль `process_search_operation.py`

Модуль содержит функции для обработки банковских транзакций:


### `process_bank_description(bank_operations: list[dict], description: str) -> list[dict]`

**Назначение:** Фильтрация банковских операций по ключевому слову в описании

**Параметры:**
- `bank_operations` (list[dict]) - список словарей с банковскими операциями
- `description` (str) - строка для поиска в описаниях операций

**Возвращает:**
- `list[dict]` - отфильтрованный список словарей, содержащих искомую строку
- Пустой список `[]` в случае возникновения ошибки

**Особенности:**
- Использует регулярные выражения для поиска
- Поиск регистронезависимый (параметр `re.IGNORECASE`)
- Безопасно обрабатывает операции без ключа "description"

**Поведение:**
- Успешный поиск: возвращает список операций, содержащих искомую строку
- Пустой результат: возвращает пустой список
- Ошибка регулярного выражения: выводит информацию об ошибке в консоль и возвращает пустой список

**Примеры использования:**
```python
# Поиск операций с "Grocery" в описании
operations = [
    {"description": "Grocery Store", "amount": 100},
    {"description": "Gas Station", "amount": 50},
    {"description": "Grocery Store", "amount": 75}
]
filtered = process_bank_description(operations, "Grocery")
# Результат: 2 операции с "Grocery Store"

# Поиск без учета регистра
filtered = process_bank_description(operations, "grocery")
# Результат: 2 операции с "Grocery Store"
```

### `process_bank_operations(data: list[dict], categories: list) -> dict`
**Назначение:** Подсчет количества банковских операций по заданным категориям

**Параметры:**
- `data` (list[dict]) - список словарей с банковскими операциями
- `categories` (list) - список категорий для подсчета

**Возвращает:**
- `dict` - словарь, где ключи - названия категорий, значения - количество операций в каждой категории

**Особенности:**
- Сравнение происходит по точному совпадению описания с категорией
- Сравнение регистронезависимое
- Использует `collections.Counter` для эффективного подсчета
- Возвращает 0 для категорий, по которым не найдено операций

**Поведение:**
- Точное совпадение: учитывает только операции, где описание полностью совпадает с категорией
- Частичные совпадения: игнорируются (например, "Grocery Store" ≠ "Grocery")
- Операции без описания: игнорируются

**Примеры использования:**
```python
# Подсчет операций по категориям
operations = [
    {"description": "Grocery", "amount": 100},
    {"description": "Grocery", "amount": 50},
    {"description": "Transport", "amount": 30},
    {"description": "Grocery Store", "amount": 75}  # Не будет учтено
]

categories = ["Grocery", "Transport", "Entertainment"]
result = process_bank_operations(operations, categories)
# Результат: {"Grocery": 2, "Transport": 1, "Entertainment": 0}

# Регистронезависимое сравнение
operations = [
    {"description": "GROCERY", "amount": 100},
    {"description": "grocery", "amount": 50}
]
result = process_bank_operations(operations, ["Grocery"])
# Результат: {"Grocery": 2}
```



### Особенности работы модуля

1. **Безопасная обработка данных:**
   - Используется `operation.get("description", "")` для избежания KeyError
   - Все исключения перехватываются и обрабатываются

2. **Эффективность:**
   - Использование генераторов списков для фильтрации
   - Применение `collections.Counter` для быстрого подсчета

3. **Гибкость поиска:**
   - Регулярные выражения позволяют сложные паттерны поиска
   - Регистронезависимый поиск делает фильтрацию более удобной

4. **Четкие критерии подсчета:**
   - Для категорий требуется точное совпадение описания
   - Все категории из списка присутствуют в результате (даже с нулевым значением)



### Зависимости

- `re` - для работы с регулярными выражениями
- `collections.Counter` - для эффективного подсчета элементов



### Рекомендации по использованию

1. **Для фильтрации по ключевым словам:** используйте `process_bank_description()`
2. **Для категоризации и подсчета:** используйте `process_bank_operations()`
3. **При работе с пользовательским вводом:** учитывайте, что `process_bank_description()` принимает регулярные выражения
4. **Для точной категоризации:** убедитесь, что описания операций точно соответствуют названиям категорий


### Обработка ошибок

Обе функции защищены от ошибок:
- `process_bank_description()`: перехватывает все исключения, выводит их в консоль и возвращает пустой список
- `process_bank_operations()`: не содержит явного перехвата исключений, но использует безопасные методы доступа к данным
